# منصة التخطيط والجودة العلمية — جمعية تحصيل المعرفة

تطبيق ويب عربي (RTL) يحوّل **مقياس الجودة التعليمية (300 درجة)** من ملف تشغيلي إلى نظام رقمي
متعدد الحسابات والصلاحيات، يوجّه كل مستخدم تلقائيًا إلى واجباته بحسب دوره والبرنامج والتوقيت،
ويحسب الدرجات والتغطية ويجمع الشواهد والتنبيهات والتقارير دون متابعة يدوية.

> **المبدأ الحاكم:** المستخدم لا يبحث عما يجب عليه فعله؛ النظام يعرض له واجباته، وموعدها،
> والنموذج المطلوب، ونسبة الاكتمال، والشواهد الناقصة.

هذه النسخة تنفّذ **المرحلة 1 (MVP)** من خارطة التطوير في وثيقة التحليل، مع أجزاء من المرحلة 2
(التنبيهات، الإجراءات التصحيحية، المقارنات، التصدير).

---

## التشغيل

المتطلب الوحيد هو **Node.js 22.5 أو أحدث** — لا توجد أي اعتماديات خارجية
(قاعدة البيانات SQLite مدمجة في Node عبر `node:sqlite`، والواجهة والخادم مكتوبان بالكامل
بمكتبات Node القياسية).

```bash
node --version      # يجب أن يكون 22.5+
npm run seed        # تهيئة قاعدة البيانات + بنية المقياس + برنامج تجريبي
npm start           # التشغيل على http://localhost:3000
```

أوامر إضافية:

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل مع إعادة التحميل التلقائي عند التعديل |
| `npm run reset` | حذف قاعدة البيانات وإعادة التهيئة من الصفر |
| `npm run seed -- --no-demo` | تهيئة بنية المقياس والحسابات دون البرنامج التجريبي |
| `npm test` | تشغيل الاختبارات (27 اختبارًا) |

## المقياس: 300 درجة

| القسم | الدرجة | المحاور |
|---|---|---|
| البيئة والمرافق والتجهيزات | **75** | تهيئة القاعات 30 · التجهيزات 20 · الضيافة 15 · سلامة المرافق 10 |
| الجودة العلمية والمحتوى والمعلم | **135** | مناسبة المعلم 25 · سلامة المحتوى 30 · الخطة والمخرجات 20 · تنفيذ المحتوى 25 · الأنشطة 15 · تقييم المعلم 20 |
| تجربة الطالب والانضباط والاستمرارية | **90** | الدعم والتواصل 20 · الرضا والانتماء 20 · المتابعة والانضباط 15 · الشكاوى 15 · الاستمرارية 20 |

17 مؤشرًا و42 عنصر تحقق و21 سؤال استبانة. **الأوزان والدوريات وخطط العينة كلها قابلة للتعديل
من شاشة «إدارة المقياس» دون تعديل الكود**، والشاشة تحذّر فورًا إذا لم يعد المجموع 300.

### قواعد الأعمال المنفّذة

| الرمز | القاعدة | موضع التنفيذ |
|---|---|---|
| BR-01 | إجمالي المقياس 300 = 75 + 135 + 90 | `src/db/framework.js` + تحقق في `/admin/metric` |
| BR-02 | متحقق 100% · جزئي 50% · غير متحقق 0% | `src/routes/dashboard.js` (نموذج التحقق) |
| BR-03 | الاستبانة: (المتوسط − 1) ÷ 4 × 100 | `likertToPct` في `src/lib/scoring.js` |
| BR-04 | الملاحظة إلزامية عند جزئي أو غير متحقق | تحقق في الخادم + المتصفح (`public/app.js`) |
| BR-05 | تهيئة القاعات: عينة ≥ 50% من اللقاءات | `periodicity: per_session_sample, sample_pct: 50` |
| BR-06 | الضيافة: عينة ≥ 25% وبحد أدنى مرتين | `sample_pct: 25, min_count: 2` |
| BR-07 | التجهيزات: مرتان على الأقل | `periodicity: fixed_count, min_count: 2` |
| BR-08 | الدعم والتواصل: المنتصف والنهاية | `periodicity: mid_end` |
| BR-09 | فاعلية النشاط الرئيس بعد كل نشاط | `scheduleMainActivityTask` في `src/lib/scheduler.js` |
| BR-10 | الاستمرارية: 5 نية + 15 فعلي | مؤشرا `I-3.5.1` و`I-3.5.2` |
| BR-11 | «اكتمال القياس» مستقل عن «نتيجة الجودة» | `computeProgram` يعيد `coverage_pct` و`quality_pct` منفصلين |
| BR-12 | لا يحكم الطالب على السلامة العلمية | أسئلة الاستبانات تُبنى من مؤشرات `tool = survey` فقط |

## الأدوار والصلاحيات

خمسة أدوار تشغيلية تُسند **داخل كل برنامج على حدة**، بالإضافة إلى صلاحيتين عامتين
(مدير النظام، مدير التخطيط والجودة). كل دور يرى مهامه المرتبطة به فقط، والحقول تظهر
حسب الصلاحية.

| الدور | أبرز صلاحياته |
|---|---|
| مسؤول البرنامج | بيانات البرنامج واللقاءات والطلاب، الحضور، الشكاوى، الانضباط، الاستمرارية، الإقفال |
| المشرف | قوائم تحقق القاعات والمرافق والتجهيزات، الشواهد، الإجراءات التصحيحية |
| مسؤول التخطيط والجودة العلمية | مناسبة المعلم، سلامة المحتوى، الخطة، تنفيذ المقرر، الأنشطة، تقييم المعلم |
| مسؤول التخطيط والجودة | استبانات الدعم والرضا، تحليل تجربة الطالب |
| مدير التخطيط والجودة | إنشاء البرامج وإسناد الأدوار، التحقق النهائي من الشكاوى، اللوحات والتقارير، سجل التدقيق |

## الوحدات المنفّذة

- **إدارة البرامج** — الفترة، الموقع، اللقاءات، الطلاب، المعلمون، الخطة، إسناد الأدوار.
- **إدارة المقياس** — أقسام ومحاور ومؤشرات وأوزان وأدوات ودوريات وقواعد حساب قابلة للإعداد.
- **الجدولة الآلية** — توليد مهام القياس من الدوريات وخطط العينة مع توزيع العينة بانتظام على اللقاءات.
- **قوائم التحقق** — 100/50/0 مع إلزام الملاحظة والشواهد وتوليد الإجراء التصحيحي تلقائيًا.
- **الاستبانات** — توليد من مكتبة الأسئلة، رابط توزيع عام بلا تسجيل دخول، نتائج فورية وفق BR-03.
- **المتابعة والانضباط** — الحضور لكل لقاء، الحالات المتعثرة، الإجراءات، قنوات التواصل.
- **الشكاوى والمقترحات** — مدة معالجة (SLA)، حالة، إغلاق موثّق، تحقق نهائي من مدير الجودة.
- **الاستمرارية** — أعداد البداية والنهاية، الانسحابات وأسبابها، نية الاستمرار.
- **الإجراءات التصحيحية والتحسينية** — لوحة كانبان بأربع حالات.
- **الشواهد** — ملفات (10 ميجابايت كحد أقصى، أنواع محددة) أو روابط، مرتبطة بأي سجل.
- **الإشعارات** — قبل الاستحقاق، عند التأخر، عند نقص العينة، وعند وجود عنصر غير متحقق.
- **التقارير** — تقرير برنامج كامل قابل للطباعة PDF، تصدير Excel (CSV بترميز عربي)، مقارنة البرامج والفترات.
- **سجل التدقيق** — من فعل ماذا ومتى مع صورة قبل/بعد لكل تعديل جوهري.
- **إقفال البرنامج** — لا يتم قبل عرض القياسات الناقصة والشكاوى المفتوحة بوضوح.

```

  server.js              الخادم والموجّه وسياق الطلب
  db/
    schema.sql           مخطط قاعدة البيانات (23 جدولًا)

    index.js             الاتصال بقاعدة البيانات والمعاملات
  lib/

    scheduler.js         توليد المهام والعينات والتنبيهات وفحص جاهزية الإقفال
    roles.js             الأدوار والمسؤوليات ومصفوفة الصلاحيات
    auth.js              كلمات المرور (scrypt) والجلسات والوصول للبرامج
    audit.js             سجل التدقيق
    http.js              قراءة الطلب، multipart، الكوكيز، الموجّه

  routes/                مسارات الشاشات (دخول، لوحة، برامج، عمليات، استبانات، شواهد، تقارير، إدارة)

docs/                    مطابقة الوثيقة بالتنفيذ وملاحظات التشغيل
```

## الأمان

- كلمات المرور بخوارزمية **scrypt** بملح فريد لكل مستخدم ومقارنة ثابتة الزمن.
- جلسات برموز عشوائية (32 بايت) في كوكي `HttpOnly` + `SameSite=Lax` بصلاحية 7 أيام.
- كل استعلامات قاعدة البيانات **مُعامَلة (parameterized)** — لا تركيب نصي لجمل SQL.
- ترميز HTML لكل مخرجات المستخدم عبر `esc()` لمنع XSS.
- تحقق من الصلاحية على مستوى البرنامج والدور في كل مسار كتابة.
- رفع الملفات مقيّد بالنوع والحجم، ويُخزَّن باسم عشوائي خارج المسار العام.
- سجل تدقيق لكل تعديل جوهري مع صورة قبل/بعد.

**قبل التشغيل الفعلي:** غيّر كلمات المرور الافتراضية، وشغّل الخدمة خلف HTTPS
(الكوكي يحتاج راية `Secure` عندها)، وفعّل نسخًا احتياطيًا دوريًا لملف `data/tpq.db`.
