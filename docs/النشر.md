# نشر المنصة برابط دائم

المشروع جاهز للنشر كما هو: يقرأ المنفذ من البيئة، ويستمع على كل الواجهات،
ويهيّئ قاعدته عند أول إقلاع، وبلا أي اعتماد خارجي (Node وملف SQLite واحد).

## الطريقة الأسرع — Render (تعمل من متصفح الجوال)

1. افتح **render.com** في متصفح الجوال وسجّل حسابًا بـ GitHub.
2. **New** ← **Blueprint**.
3. اختر مستودع `rakanalaql0-wq/tahseel-planning-quality` والفرع
   `claude/platform-planning-quality-hl955j`.
4. يقرأ Render ملف `render.yaml` في جذر المستودع ويهيّئ كل شيء. اضغط **Apply**.
5. بعد دقيقتين يظهر رابط ثابت بالشكل:
   `https://tahseel-planning-quality.onrender.com`

### كلمة المرور الأولى

يولّد Render كلمة مرور عشوائية ويضعها في متغير `TPQ_SEED_PASSWORD`.
اقرأها من: **لوحة الخدمة ← Environment ← TPQ_SEED_PASSWORD**، وادخل بها
بالحساب `admin`.

لا تُطبع كلمة المرور في سجلّات النشر — السجلّات تُحفظ وتُقرأ، فطباعتها فيها تسريب.

## قبل إدخال أي بيانات حقيقية

ثلاثة أمور لازمة، ولا أنصح بإدخال بيانات طلاب أو شكاوى قبلها:

| الأمر | كيف |
|---|---|
| **إيقاف بيانات العرض التجريبي** | اجعل `TPQ_DEMO = 0` في Environment |
| **قرص دائم للبيانات** | الخطة المجانية بلا قرص: تضيع البيانات عند كل إعادة تشغيل. ارفع الخطة، ثم أزِل التعليق عن كتلة `disk` في `render.yaml` واجعل `TPQ_DB = /var/data/tpq.db` |
| **نسخ احتياطي** | ملف واحد هو `TPQ_DB`. انسخه دوريًا خارج الخادم |

## ملاحظات على الخطة المجانية

- **تنام الخدمة** بعد خمس عشرة دقيقة بلا زيارات، فيتأخر أول طلب بعدها نحو
  نصف دقيقة حتى تستيقظ. هذا مقبول للعرض، ومزعج للاستخدام اليومي.
- **لا قرص دائم**، فالبيانات مؤقتة كما سبق.

الخطتان معًا تجعلان الخطة المجانية صالحة **للعرض والتجربة** لا للتشغيل الفعلي.

## متغيرات البيئة

| المتغير | معناه | الافتراضي |
|---|---|---|
| `PORT` | منفذ الاستماع | `3000` |
| `HOST` | واجهة الاستماع | `0.0.0.0` |
| `TPQ_DB` | مسار ملف قاعدة البيانات | `data/tpq.db` |
| `TPQ_SEED_PASSWORD` | كلمة مرور الحسابات الأولى | `Tahseel@2026` |
| `TPQ_DEMO` | `0` يمنع بيانات العرض التجريبي | `1` |
